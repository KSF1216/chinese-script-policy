# 離線單檔網頁版的細節（從 README 搬過來）

> README 只留「下載、雙擊」兩句；建置方式與 Pages 線上版在這裡。

## 離線單檔網頁版（給沒有 LLM 的機器用）

**要拿到檔案有三條路，選一條就好**：

| 你要什麼 | 怎麼做 | 需要 Node 嗎 |
|---|---|---|
| **只想用**（最省事） | 下載 [`dist/tradzh.html`](dist/tradzh.html)——GitHub 上直接點開按 **Download raw file**，或整包 **Code → Download ZIP** 之後解開找 `dist/tradzh.html` | ❌ **不用** |
| 從 npm 安裝 | `npm i chinese-script-policy`，檔案在 `node_modules/chinese-script-policy/dist/tradzh.html` | 只有安裝時要 |
| 自己重建（改了字表） | `npm run build:web` → 產生 `dist/tradzh.html`（約 1.33 MB） | ✅ 要 |

下載後**雙擊就能用**：整個頁面是一個檔案，字表與程式都內嵌在裡面，沒有外部檔案、
沒有 CDN、沒有網路請求（可以離線、可以放 USB、可以 email 給別人）。

> **為什麼這個產生物要進版控**（其他專案通常不這樣做）：它的價值就是「下載即用」，
> 不進版控的話**沒有任何人有辦法下載到現成的一份**——只能自己 clone 加裝 Node 再建置，
> 那就違背了「給沒有 LLM／沒有 Node 的機器用」這個目的。
> 相對應的代價是「committed 的檔案可能過期」，所以 `npm run test:web` 會**重建一次並逐位元組比對**，
> 過期就測試失敗（建置本身是可重現的：頁尾印的是**版本號**，不是建置日期）。

### 線上版（選用：GitHub Pages）

repo 根目錄有兩個只為此存在的小檔，**不影響下載、不影響 npm、不影響 skill 安裝**：

| 檔案 | 作用 |
|---|---|
| `index.html` | 只做轉址到 `dist/tradzh.html`，讓 Pages 的**根網址就能直接開工具**（不然根網址會 404，因為 repo 裡本來沒有 `index.html`）。刻意不複製任何內容——工具永遠只有一份 |
| `.nojekyll` | 告訴 GitHub Pages **不要**用 Jekyll 處理這個 repo（細節見 [`PUBLISHING.md`](PUBLISHING.md)） |

在 `Settings → Pages → Deploy from a branch → main / (root)` 開啟之後，網址會是
`https://<你的帳號>.github.io/chinese-script-policy/`。**開啟與否都不影響 clone／ZIP／npm**，
Pages 只是在同一個 repo 上多一層提供方式。

**一個頁面同時負責轉換與檢查**：

| 位置 | 內容 |
|---|---|
| 最上面 | 腳本軸兩方向（**繁體預設開／簡體預設關**，二選一）＋ 兩條副軸（書面語、日文，預設開）＋讀入檔案的編碼 |
| 第 2 格 | **原文**輸入框 |
| 第 3 格 | **原文的檢查結果**：摘要卡、行號、標示色（跟著原文即時更新；每條軸一個顏色） |
| 中間 | **繁轉簡**、**簡轉繁**、**用語偏好**（選用；簡轉繁用繁體偏好、繁轉簡用簡體偏好，勾選狀態會記住），還有開啟檔案、複製結果、結果送回原文、全部清空 |
| 最下面 | **結果**框，以及「結果有沒有殘留」的判定 |

由上往下讀就是「**原文 → 哪裡有問題 → 轉換 → 結果**」。這個順序有測試在釘
（`npm run test:web` 會檢查 `#input`、`#summary`、`#report` 都排在 `#to-simplified` 前面）。

**原文是貴重的，所以轉換不會碰它。** 兩顆轉換按鈕一律把結果寫到**結果框**，
原文欄只有在你**自己按下「結果送回原文」**時才會被取代（拖入檔案也一樣：
原文欄已有內容時，檔案會放到結果框）。

| 特點 | 說明 |
|---|---|
| 單一檔案 | 沒有外部檔案、沒有 CDN、沒有網路請求；複製到任何機器（USB、email、雲端硬碟）雙擊就能用 |
| 完全離線 | 不上傳任何文字；沒有追蹤、沒有分析 |
| 原文不動 | 轉換只寫結果框；`npm run test:web` 會實際「按」按鈕並斷言原文欄沒被改動 |
| 轉完自動複查 | 結果框下方立刻說有沒有殘留（`後面` 那種詞組例外會標紅要你自己確認） |
| 讀舊檔 | 拖入 `.txt`／`.md` 時自動判編碼（UTF-8／BOM／Big5／GB18030）；認出是日文、韓文或西歐單一位元組編碼時會說「不是中文檔」而不是硬讀成亂碼 |
| 與 CLI 同源 | 頁面內嵌的就是 `scripts/core.js` 與同一組字表；`npm run test:web` 會拿 CLI 用的同一組測試資料比對，也會用假的 DOM 真的「按」按鈕 |
| 不會過期 | committed 的 `dist/tradzh.html` 每次 `npm test` 都會被重建比對，與字表不同步就失敗 |

改了任何字表 → `npm run build:web`，**然後把 `dist/tradzh.html` 一起提交**（測試會檢查）。
