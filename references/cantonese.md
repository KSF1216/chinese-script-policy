# 副軸：粵語口語 vs 書面語

> 這是 `SKILL.md` 的細節補充。**要改粵語字表、或想知道轉換到什麼程度**時才看。

## 為什麼這是「副軸」而不是主軸的另一邊

| 軸 | 差別 | 可不可以查表 |
|---|---|---|
| 字形（繁／簡） | 說 / 说 | ✅ 可以（有限映射） | <!-- simplified-example -->
| 字形變體 | 裡 / 裏 | ✅ 可以（少量偏好） |
| **語體（粵語口語／書面語）** | 嘅 / 的、我哋 / 我們 | ⚠️ **詞彙可以，語法不行** |

**資料儲存一律用書面語**：粵語母語者本來就讀書面語，所以儲存層轉書面語不會損失可讀性。

## 轉換：只轉「不可能出現在書面語」的那一半

`--to-written` 是**真的會轉**，但範圍刻意收得很窄。判準只有一條：

> **這個字串在書面中文裡根本不可能出現，才自動轉。**

實作上就是：鍵裡含有**粵語專有字**（`chars` 那 17 個），或含有 `唔`（普通話的「唔」是感嘆詞，後面一定接標點）。

| 會轉（12 字＋17 詞） | 不轉，只偵測 |
|---|---|
| `嘅`→`的`、`咗`→`了`、`喺`→`在`、`佢`→`他`、`哋`→`們`、`嘢`→`東西`、`嗰`→`那`、`嘥`→`浪費`、`唞`→`休息`、`攰`→`累`、`冇`→`沒有`、`嚟`→`來`；`唔該`→`謝謝`、`有冇`→`有沒有`、`唔知`→`不知道`、`乜嘢`→`什麼`… | `屋企`、`邊度`、`得閒`、`而家`、`點解`、`食飯`、`好食`、`頭先`、`先至`、`呢個`、`大佬`、`諗住`… |

**為什麼 `屋企`、`點解` 這麼常見卻不轉**：它們**每個字都是標準字**，而且會在書面中文裡**跨詞邊界**出現：

| 粵語詞 | 書面中文裡的真實字串 |
|---|---|
| 屋企 | 房**屋企**業 |
| 邊度 | 旁邊**度**過 |
| 得閒 | 取得**閒**置 |
| 而家 | 因而**家**庭 |
| 食飯 | 飲食**飯**店 |
| 好食 | 喜好**食**物 |
| 點解 | 早點**解**決 |
| 頭先 | 從**頭先**看一遍 |
| 先至 | 由**先至**後 |

這是跟 `方便面`→`方便麵` 完全一樣的子字串陷阱，而且這裡的阻擋項永遠列不完。**偵測還是會把這些詞抓出來**（不會沉默），只是改寫要交給模型。

**語法層永遠不轉**（語序與句式，查表做不到）：

| 粵語 | 書面語 | 問題 |
|---|---|---|
| 你行先 | **你先走** | 語序不同 |
| 我食多啲 | **我多吃一點** | 程度補語位置不同 |
| 畀本書我 | **給我一本書** | 雙賓語語序不同 |
| 佢大過我 | **他比我大** | 比較句結構不同 |
| 有冇 / 係咪 / 得唔得 | **有沒有 / 是不是 / 行不行** | 正反問句要展開 |

⚠️ **而且這幾種連偵測都抓不到**：`你行先`、`畀本書我`、`我食緊飯` 實測都是 `RESULT: clean`——我們的表只有字元層與詞組層，語序型粵語沒有任何標記。**這是已知的漏抓**（寧可漏，不要誤判的方向），要補就得加句法樣式（`V+先`、`V+緊`），那是另一個決定。

### 部分轉換不能看起來像全部

兩個機制保證這件事：

1. **轉完會列出轉不到的**：`tradzh` 把剩下來的粵語／日文標記寫到 stderr（`note - the converted text still has …`），要模型接手改寫。
2. **寫入仍然會被擋**：`--to-written` 的把關軸就是語體軸，殘留的標記會讓寫入被拒絕（除非 `--force` 或該行標了 `check-ok`）。

還有一個小限制要知道：**部分轉換會讓詞組偵測失效**。`我食咗飯` → `我食了飯`（`食` 是標準字，所以只動 `咗`），但這一步之後 `食飯` 這個詞組就不再匹配了——結果「乾淨」但其實還不是標準書面語。定位要講清楚：**這一步是「拿掉一定不是書面語的字」，不是「產生完美書面語」**。

## 步驟順序（唯一正解）

```
日文 → 語體 → 腳本（繁／簡）
```

```powershell
node scripts\tradzh.js --convert-japanese --write a.txt < in.txt   # 1. 清日文
node scripts\tradzh.js --to-written       --write b.txt < a.txt    # 2. 轉書面語
node scripts\tradzh.js --to-traditional   --write c.txt < b.txt    # 3. 轉繁／簡
```

順序不能顛倒：`竜` 在「繁→簡」表裡沒有條目，必須先變繁體才能變簡體（`竜`→`龍`→`龙`）。**顛倒了不會沉默**——`龍` 在簡體軸是違規，檢查會抓到。  <!-- check-ok -->

## 偵測的四層（缺一不可）

| 層 | 抓什麼 | 例子 | 需要佐證嗎 |
|---|---|---|---|
| **字表 `chars`** | 幾乎只出現在粵語的字 | 嘅 咗 喺 佢 哋 啲 嘢 咁 噉 嗰 啱 嘥 冧 唞 攰 冇 嚟 | 不用（本身就是證據） |
| **詞組 `phrases`** | 每個字都是標準字、但整組是粵語 | 唔該 有冇 嗰個 乜嘢 係咪 返屋企 | 不用 |
| **弱詞組 `weakPhrases`** | 粵語詞，但**正常中文也會跨詞出現** | 點解（早點解決）、屋企（房屋企業）、邊度（旁邊度過）、先至（由先至後）、仲有（仲裁有） | **要**：同一行還要有上面兩層或樣式命中 |
| **句法樣式 `patterns`** | 語序（表永遠看不到） | `V先`（行先）、`V緊`（食緊）、`畀…我` | 不用（本身就是證據） |

**為什麼弱詞組要佐證**：`點解`／`屋企`／`邊度` 這些在正常中文裡會**跨詞邊界**出現，
實測「房屋企業在旁邊度過，早點解決問題。」在單純子字串比對下會產生 **3 個命中**，
而寫入 hook 會直接擋掉一句完全正常的中文。加了佐證規則之後同一句是 clean。

**代價（刻意接受）**：只用弱詞組、而同行沒有其他標記的句子（例如單獨一句「點解你要走？」）
**不會被標記**。這符合專案的「寧可漏，不要誤判」——誤判會擋掉寫入，漏抓只是少一個提示。
`selftest` 的 `written` 段把兩邊都釘住（17 個案例，含「必須乾淨」的跨詞陷阱）。

**句法樣式的假警報護欄**：每個樣式都帶 lookahead 排除正常中文的跨詞巧合——
`實行先進`、`演講先生`（V先）、`零食緊缺`、`緊急`、`緊張`（V緊）。樣式是啟發式，
所以它們只做偵測、不參與轉換。

**共用的字只能放詞組表**（放字表會誤判）：

| 字 | 標準中文也在用的證據 | 結果 |
|---|---|---|
| 係 | 關係、係數 | 只出現在 `係咪` |
| 唔 | 普通話感嘆詞「唔」 | 只出現在 `唔該`、`唔係`… |
| 睇 | 古漢語「睇」＝看 | 只出現在 `睇下` |
| 幾 / 邊 / 傾 / 諗 / 畀 / 俾 / 郁 / 靚 | 幾個、旁邊、傾談、文言「畀予」「俾使」、濃郁、靚妝 | 只出現在 `幾時`、`邊度`、`傾偈` 等 |

**刻意不收的**（寧可漏抓，不要誤判）：

| 項目 | 為什麼 |
|---|---|
| 咩 | 普通話的羊叫聲「咩咩叫」→ 只留詞組 `有咩` |
| 收工 | 標準中文也用（＝收尾） |
| 幾時 | 古詩也用（「青天有月來幾時」） |
| 返工 | 標準中文指「重做、退貨返工」，與粵語「上班」撞義 |
| 句末助詞（喇／喎／噃／啩） | v1 未收：`喇` 會撞「喇嘛」，其餘待人工審核後再加 |

**✅ 已知誤判：2026-09 修好（就是上面那條佐證規則）**。修好之前的實測：

```text
$ node scripts\tradzh.js --written --text "房屋企業在旁邊度過，早點解決問題。"
FAIL  3 occurrence(s): 屋企 邊度 點解        ← 正常中文被當成粵語，hook 會擋掉寫入
```

修好之後同一句是 `RESULT: clean`. 作法是**不動偵測清單**，只要求弱詞組要有同行佐證，
所以跨詞巧合自動消失，而「我哋而家去邊度食飯」這種真的粵語句照樣被抓（`哋` 是強標記）。

**另一個可能的作法（沒有採用）**：把弱詞組的命中降級成「只提示、不擋寫入」的 NOTE。
那樣子連單獨一句「點解你要走？」都會被提示到，代價是檢查流程要分成兩種嚴重度
（CLI 的 exit code、hook 的擋與不擋、網頁的標記顏色都要跟著分）。目前維持單一嚴重度。

## 放行機制（兩層）

| 機制 | 範圍 | 檔案 |
|---|---|---|
| `.tradzhignore` | 整個檔案跳過**所有**檢查 | 專案根目錄或 skill 根目錄 |
| **`cantonese-allow.json`** | 只跳過**語體軸**；繁體與簡體照抓 | **專案根目錄**（`cwd`），不隨工具發布 |
| `check-ok` 行內標記 | 該行（或下一行）跳過所有檢查 | 任何檔案 |

```json
{
  "allow": [
    { "path": "**/dialogue/*.md", "why": "角色台詞原文，保留粵語語氣" },
    { "path": "**/corpus/**", "why": "語料，本來就是粵語" }
  ]
}
```

`path` 用跟 `.tradzhignore` 完全相同的 glob 語法（同一支轉換器，避免兩套方言）。
CLI（`--written --dir`）與寫入 hook 都讀同一份清單，所以兩者不會對同一個檔案給出不同答案。

## 維護

改了 `scripts/cantonese-only.json` 之後跑：

```bash
node scripts/selftest.js
```

裡面有 **19 個語體偵測案例 ＋ 54 個轉換檢查**（`writtenConvert` 段）：

* 偵測的**「乾淨」那幾個比「抓到」重要**——它們就是上面那些陷阱（關係／幾個／旁邊／咩咩叫／收工／返工／幾時），是防止過度偵測的護欄。
* 轉換的**「不該動」那幾個更重要**——`房屋企業`、`早點解決`、`取得閒置`、`因而家庭`、`飲食飯店`、`喜好食物`、`從頭先看`、`由先至後` 必須原樣不動。誰哪天把 `屋企`／`點解` 加進 `convertPhrases`，這一段就會 FAIL，而不是安靜地把正常中文改壞。
* 同一組 fixture 也驗**冪等性**：轉完的結果再跑一次同一步，必須完全不變。
