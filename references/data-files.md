# 資料檔一覽：每一份存什麼（從 README 搬過來）

> 維護字表、或想知道「哪個數字寫死在哪些檔案」時看這份。

## 資料檔一覽（每一份存什麼）

字表就是一組**取捨**：`峰` 算不算繁體、`靚` 算不算粵語、某個詞算不算日文，
不同領域的習慣不太一樣。這裡的原則是**寧可漏抓、不要誤判**，所以預設值偏保守。
以下都是可以直接打開來看的 JSON：

| 檔案（在 `scripts/`） | 存什麼 | 筆數 |
|---|---|---|
| `simplified-only.json` | 簡體專有字（只在簡體出現的字） | 2,637 字（純陣列） |
| `traditional-only.json` | 繁體專有字（要求簡體時抓的就是它） | 3,083 字（純陣列） |
| `cantonese-only.json` | 粵語口語：字、詞組、弱詞組、語序樣式，以及可轉換的對照 | 17 字、30 詞、15 弱詞組、3 樣式；可轉換 12 字＋17 詞 |
| `japanese-only.json` | 日本新字體與和製漢字（`chars`）、對照表（`map`）、日文詞（`phrases`） | 367 字、346 對照、123 詞 |
| `simplified-to-traditional.json` | 簡→繁：字表、詞組表、字形偏好 | 4,012 字、49,257 詞、41 字形 |
| `traditional-to-simplified.json` | 繁→簡：字表、詞組表 | 4,148 字、480 詞 |
| `tc-vocabulary.json` | 用語偏好（繁體偏好），`--wording` 才用 | 830 筆 |
| `sc-vocabulary.json` | 反向用語偏好（繁體偏好 → 簡體偏好），`--wording` 才用 | 810 筆 |
| `cjk-compatibility.json` | 相容表意文字 → 標準字（同一個字有兩個碼位） | 1,002 筆 |
| `glyph-preferences.json` | 字形偏好（收斂到常見寫法：裡、麵、為） | 41 筆 |

**前四份是偵測表，沒有重建腳本**——改了就是改了。後六份由 `build-s2t.js`／`build-jp.js`
重建；**詞組、字形與用語偏好層的本地修正會保留**（列在檔案的 `$localEdits` 標頭），字元層則整份重寫。

調整時只有一條原則：**繁簡同形字不要放進偵測清單**（`您 什麼 可以 我` 這類），
那會把正常繁體判成簡體。改了字表就再跑 `npm test`；加減字之後另外跑
`npm run audit`（Big5／cp950 稽核，需要 Windows PowerShell）看有沒有假警報。

### 不改表也能達成的四件事

| 需求 | 用這個 | 放在哪 |
|---|---|---|
| 這個專案是粵語原文，語體軸別管 | `cantonese-allow.json`（只跳過語體軸，簡體與日文照抓） | 你的專案根目錄 |
| 這些檔案本來就是簡體（locale、上游程式碼） | `.tradzhignore`（整檔跳過所有軸） | 你的專案根目錄 |
| 只有某一行要放行 | 在那一行寫 `check-ok` 或 `simplified-example` | 檔案裡（標記也會跳過**下一行**） |
| 這個專案存的是簡體 | 外掛設定卡把腳本軸切成「要求簡體」 | DSH 的外掛設定 |

> 這兩個豁免檔讀的是**執行時 cwd**：CLI 在你執行它的目錄讀、DSH 外掛在 session 工作區讀，
> 所以要放在**你要保護的那個專案根目錄**才會生效。
